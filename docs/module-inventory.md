# Workspace module inventory

Task 4 snapshot, 8 October 2026. “Current” means implemented in this branch; it does not guarantee that a given tenant has consented to Graph, assigned the workspace module, granted the signed-in user a suitable Entra role, or activated an eligible role through PIM. Workspace module grants and Microsoft authorization are separate checks. Future concepts below are planning candidates only: they have no active route, sidebar entry, workspace module grant, or promised delivery date. Wave 1 planning does not mean a feature is shipped, enabled, validated, or granted.

The `authentication.campaigns.view` capability and `authentication-campaigns` module are active contracts, but each workspace must deliberately enable the module and each user must pass the API's authorization checks. `licenses.hygiene.view` and `license-hygiene` are active opt-in module/capability contracts. Neither module is enabled by default; users must also pass the API's authorization checks.

The following identifiers remain reserved and inactive: `authentication.campaigns.manage`, `platform.about.view`, and `feedback.submit`. Their presence in frontend and backend reserved-capability lists does not activate a route, capability decision, module grant, or feature. Enabling or documenting License Hygiene does not automatically grant the module to a workspace or member.

No remaining deferred candidate should appear as a placeholder page or be enabled in a workspace until its source, least-privilege permission contract, failure states and tenant test are defined.
