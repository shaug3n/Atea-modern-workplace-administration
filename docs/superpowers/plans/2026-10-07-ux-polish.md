# UX Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Atea Unified Workplace UI feel like one calm, professional admin product by resolving the 52 in-scope findings of the UX inspection (all 18 Critical/High) without changing routes, API contracts, auth boundaries or confirmation safety.

**Architecture:** Add a token/semantic CSS layer (`foundations.css`, `components.css`, imported after `theme.css`), evolve the existing shared components in place (backward-compatible props), add a few small primitives (`TechnicalDetails`, `CopyValue`, `MetricCard`, `ActionGroup`, `Icon`, `DateTime`, `ModuleUnavailable`, `format/*`), then migrate shell and pages onto them. No new dependencies.

**Tech Stack:** React + TypeScript + Vite (`src/Web`), vitest/jsdom + testing-library, `node --test`, .NET (only `LicenseDisplayNameResolver` changes).

**Spec:** `docs/superpowers/specs/2026-10-07-ux-polish-design.md` (source of truth — copy strings, tones, layouts and the UX-ID table live there; this plan says *where* and *how*, the spec says *what exactly*). Evidence: `docs/ux-inspection/report.md`, `docs/ux-inspection/screenshots/`.

## Global Constraints

- Work only in this worktree on the already checked-out branch `shaug3n-ux-visual-inspection`. Do not create branches. One PR.

- Routes, API request/response contracts, auth boundaries, capability gating and every existing destructive-action confirmation (typed phrase, reviewed checkbox, source-limitation block) are preserved. No new Microsoft 365 operations. Disabled modules stay hidden from nav.
- Tests whose wording changes are **updated, never deleted**. Test files live in `tests/Web.UnitTests/**` (vitest `*.test.tsx`, imports like `../../../src/Web/src/components/X`) and `tests/Web.E2E/*.spec.tsx`; node contract tests are `tests/Web.UnitTests/*.test.mjs` and must be listed explicitly in `tests/Web.UnitTests/package.json` `test` script (it names files one by one).
- CSS: new rules go in `src/Web/src/styles/foundations.css` (tokens/base) or `components.css` (components/shell), imported in `main.tsx` **after** `./styles/theme.css`; no `!important`. Delete a `theme.css` rule only when fully superseded. `theme.css` must keep `--uw-primary`, `:root[data-theme='dark']`, `.button--primary`, `.page-action-bar`, `.detail-card` (asserted by `theme-and-catalog.test.mjs`); `ThemeToggle.tsx` must keep `role="switch"`.
- Copy rules (spec §3.5): sentence case; buttons are verb + object ("Disable user", never "Confirm action"); back links "Back to {Section}"; setup link "Open setup" (`/settings#connection`); PIM link "Open PIM guidance" (`/identity`); no GUID / SKU ID / Graph class name / capability key / scope name / JSON / correlation ID in primary content — only inside `TechnicalDetails` or `CopyValue`.
- Colour rules (spec §3.1): green (`--uw-primary`) only for the one primary action per surface and the active-nav indicator; red only for destructive actions/danger zones, never for counts (notification badge = warning tone). Tone is never the only signal.
- Accessibility (spec §7): contrast text ≥ 4.5:1 / non-text ≥ 3:1 both themes; targets ≥ 24px (icon buttons 40px); one H1 per page with `id="page-title"`; no page-level `aria-label` sections duplicating the H1; native `<details>` for disclosures; polite/`role=status` live regions only.
- Fixed command sets used by checkpoints (run from repo root; run `npm ci --prefix src/Web` once if `src/Web/node_modules` is missing):
  - **WEB-CHECK:** `cd src/Web && npm run build && npm test && npm run test:behavior && cd ../../tests/Web.UnitTests && npm test && cd ../Web.E2E && npm test`
  - **Focused vitest:** `cd src/Web && npm run test:behavior -- <FileNameFragment>`
  - **API-CHECK** (only when `src/Api` or `tests/Api.*` change): `dotnet build Atea.UnifiedWorkplace.sln && dotnet test tests/Api.UnitTests/Api.UnitTests.csproj` (SDK pinned by `global.json`; **`dotnet` is not installed in the planning environment** — if still missing, skip and rely on CI, and say so in the PR notes).

## Review Focus

Failure modes the spec implies but no single task's happy path exercises (each is pinned by a test in the owning task):
1. **Very long unbroken values** (60-char UPN, 36-char GUID, unknown SKU part number) must not widen the page or break mid-word in tables/compact lists — Tasks 5, 12, 15, 18.
2. **Entities with a null/empty display name** show a type placeholder ("Unnamed device", UPN/email fallback), never a GUID in a heading or cell — Tasks 13, 14, 15, 16.
3. **Clipboard API missing or rejecting** must not throw, must not announce "Copied", and must hide/keep the control usable — Task 5.
4. **Invalid, missing or future timestamps** render "—"/absolute text, never "Invalid Date"/"NaN" — Task 3.
5. **Unknown enum values** (capability key, auth-method type, role assignment state, activity action, unrecognised SKU) fall back to a safe label and never leak the raw key into primary content — Tasks 3, 17, 18, 19.
